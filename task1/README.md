## Условие

Первая программа выбирает самый большой по размеру в байтах файл
из /var/data и копирует его в /var/result/data.txt.
При одинаковом размере выбирается первый файл по имени.
Исходные файлы сохраняются для повторного запуска.

Вторая программа читает /var/data/data.txt, вычисляет произведение
первого и последнего целого числа, записывает ответ
в /var/result/result.txt и выводит его на экран.

## Состав проекта

- worker1/app.py — первая программа.
- worker2/app.py — вторая программа.
- worker1/Dockerfile и worker2/Dockerfile — сборка образов Python 3.14.
- compose.yaml — сборка и последовательный запуск сервисов.
- data/ — исходные файлы с целыми числами.
- result-1/ — промежуточный результат.
- result/ — окончательный результат.

## Передача данных

| Каталог на хосте | worker1 | worker2 |
|---|---|---|
| ./data | /var/data, только чтение | — |
| ./result-1 | /var/result | /var/data, только чтение |
| ./result | — | /var/result |

Используются bind mounts.
Сервис worker2 запускается после успешного завершения worker1:
depends_on с условием service_completed_successfully.

## Запуск

Требуются Docker Desktop с Linux-контейнерами и Docker Compose.
Команды выполняются из каталога task1.

```powershell
docker compose config -q
docker compose up --build
```

## Проверка результата

```powershell
docker compose ps -a
Get-Content .\result-1\data.txt
Get-Content .\result\result.txt
```

Оба контейнера должны завершиться с кодом 0: Exited (0).
Это ожидаемое поведение программ, выполняющих одно вычисление.

На подготовленных данных выбирается large.txt.
Первое число — 7, последнее — 9.
Ожидаемый и полученный результат: 63.

## Повторный запуск

```powershell
docker compose up --build --force-recreate
```

## Удаление контейнеров проекта

```powershell
docker compose down
```

Файлы в каталогах хоста сохраняются.

## Исключения Git и Docker

.gitignore исключает временные файлы Python и результаты вычислений.
Файлы .gitkeep сохраняют структуру пустых каталогов результатов в Git.
Исходные данные включаются в репозиторий.

В каждом каталоге worker имеется .dockerignore:
он исключает временные файлы из соответствующего контекста сборки.
